# Wearable Data Quality and LLM Health Explanations

This Honours project investigates how wearable-data quality affects health explanations generated by general-purpose LLMs. It uses Fitbit CSV files to create baseline, missing-data, and noisy conditions, then prepares consistently structured inputs and internal validation reports.

The repository currently implements data manipulation, processing, and structural validation for seven data streams. The model interaction and response evaluation workflow is proposed in [LLMINPUT.md](LLMINPUT.md); automated model calls and response scoring are not implemented here.

## Setup and running

Dependencies are Python, pandas, and NumPy:

```powershell
python -m pip install pandas numpy
```

To inspect source files:

```powershell
python inspect_data.py
```

To generate and process one stream:

```powershell
python manipulate_dailyactivity.py
python process_dailyactivity.py
```

If experimental files already exist, run only the corresponding processor. Manipulation and processing scripts overwrite their respective outputs; close CSVs in Excel if Windows prevents writing them. Original files in `data_files/` are read, not overwritten.

To process all seven existing experimental datasets, run these commands sequentially:

```powershell
python process_dailyactivity.py
python process_heartrate.py
python process_h_steps.py
python process_h_calories.py
python process_intensities.py
python process_sleep.py
python process_weightlog.py
```

## Data workflow

```text
Source Fitbit CSVs
    -> Manipulation: baseline / missing / noisy conditions
    -> Processing: column selection, timestamps, numeric types
    -> LLM input CSVs + internal validation reports
    -> Planned participant-window selection and standardized prompts
    -> Planned response collection and evaluation
```

### Experimental conditions

Each manipulation script uses `np.random.default_rng(42)` and produces four files in its dataset folder:

| File | Contents |
|---|---|
| `baseline.csv` | Source measurements with parsed timestamps; no intentional corruption |
| `missing_10_percent.csv` | Approximately 10% of targeted measurement cells replaced with missing values |
| `noisy_data_internal.csv` | Noisy measurements plus original timestamp and available corruption metadata |
| `noisy_data.csv` | The same noisy rows without experimental metadata |

For noisy data, rows are randomly divided into three groups. Approximately 10% of each group is selected for one manipulation: timestamp shifts, random numerical variation, or extreme spikes. The combined file contains all rows, including rows that were not selected for changes. Timestamp shifts modify timestamps in place and can create duplicate participant-time records.

Daily activity masks cells across 13 measurement columns. Other streams target one measurement: heart rate `Value`, steps `StepTotal`, calories `Calories`, intensities `TotalIntensity`, sleep `value`, or weight `WeightKg`. Related measurements remain unchanged. Rounding or clipping can leave a selected value unchanged.

### Processing and internal evaluation

Processing scripts read the three experimental conditions and:

- Validate required columns and retain only original wearable columns.
- Standardize dates to `YYYY-MM-DD` for daily activity and timestamps to `YYYY-MM-DD HH:MM:SS` for other streams.
- Convert measurement columns to numeric types without filling missing values.
- Preserve row order, duplicate records, and manipulated measurements.
- Export three CSVs to `llm_inputs/<dataset>/` and a `validation_report.csv` to `evaluation/<dataset>/`.

Reports contain condition, row and participant counts, missing measurement cells, duplicate participant-time records, and negative measurement cells. Duplicate counts represent occurrences after the first. Daily activity uses slightly different report column names from the other streams.

Validation reports describe data structure; they do not repair errors, establish clinical validity, or detect every implausible value. A baseline is an unmanipulated reference and may already contain missing values or duplicates.

Corruption metadata stays in `experimental_data/<dataset>/noisy_data_internal.csv`. Steps and calories currently record group-level `corruption_type` but no per-row `was_corrupted` flag. Original timestamp fields are populated for the timestamp-shift group; for other groups, reference matching can use the current timestamp when the original field is blank.

## Preparing inputs for LLMs

The processed CSVs exclude experimental metadata but still contain participant identifiers and condition-revealing filenames. They are intermediate data, not the final blinded prompts.

The proposed next stage in [LLMINPUT.md](LLMINPUT.md) selects the same participant and underlying time window across conditions, removes participant identifiers, and creates a standardized text table. It uses the same neutral instructions for each model and condition. Hide condition labels in filenames and keep original timestamps and corruption flags out of model inputs.

Keep condition mappings, reference values, and response provenance internally for evaluation. Timestamp-shifted records should be matched through internal reference information rather than selecting each condition independently by its altered dates.

## Supporting utilities

- `inspect_data.py`: prints source-file shapes, columns, sample rows, and missing-value counts.
- `validate.py`: prints sleep and weight baseline/noisy reference-key comparisons and shifted-row counts. Sleep keys include participant, log ID, and reference time; weight keys use participant and log ID. It is a diagnostic script, not an automated assertion-based test suite, and does not validate all seven streams.
- `inject_missing.py`: a separate configurable utility supporting multiple missingness levels, random or block patterns, value masking or row removal, and flags plus a manifest. Block lengths are measured in rows. It is not called by the dataset-specific manipulation scripts.

Example using the alternative missing-data utility:

```powershell
python inject_missing.py data_files/heartrate_seconds_merged.csv --value-cols Value --id-col Id --time-col Time --levels 0.10 0.25 0.50 --pattern random --seed 42 --out-dir missing_out
```

## Current limitations and next steps

- Sleep has duplicate participant timestamps in the baseline; weight logs have pre-existing missing measurements. These are retained and reported.
- Sleep-state codes are preserved without clinical interpretation or code-range validation.
- Weight changes affect `WeightKg` while `WeightPounds` and BMI stay unchanged. Intensity changes affect `TotalIntensity` while `AverageIntensity` stays unchanged. These relationships can reveal inconsistencies and affect the experiment.
- Random seeds support repeatability with the same inputs and software environment; processing does not independently prove reference alignment for every stream.
- Model submission, response storage, evaluation rubrics, and scoring remain future work. Proposed comparisons and measures are described in `LLMINPUT.md` and will need a reproducible experiment specification.

See the dataset READMEs for extracted variables, manipulation details, current validation counts, and dataset-specific limitations.
